# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Security
- Authentication hardening (#7): Data Protection keys encrypted at rest with a certificate, mandatory outside Development (`DataProtection:CertificatePath`; compose mounts the `.pfx` and its password file, `DataProtection:CertificatePasswordFile`, as Docker secrets with mode 0400, see `docs/authentication.md`); startup refuses `AllowedHosts` empty or `*` outside Development; per-IP rate limit with `429` and `Retry-After` on `/api/auth/*`; sign-in cookies expire after 10 minutes; structured audit events for sign-in, sign-out, failed sign-in and rate limiting (user id only); one database query per authenticated request for session and user.

### Changed
- The Content Security Policy now allows images from `https://*.googleusercontent.com` (Google avatars). An unsafe method on any `/api` route without a valid antiforgery token now answers `400`, before routing.

### Added
- Playback (#10): Tone.js 15.1.22 (MIT, pinned, lazy chunk of 58 KB gzip, not in the initial bundle) with sampled instruments (Ogg Opus, CC0 sources recorded in `THIRD_PARTY_NOTICES.md`, 1.34 MB for 8 sets, only the sets used are downloaded, same-origin hashed immutable files): classical guitar, ukulele, cello, piano, flute, violin, clarinet, double bass; the steel-string guitar plays the nylon guitar and the voice plays the flute (no permissively licensed recording found). Score to timed events (tempo changes, dots, merged ties, triplets, rests, chords, voices, transposition, pickup), look-ahead scheduling, transport bar (play/pause `Space`, back to start `Home`, stop, play from selection, loop, tempo 25 % to 200 %, metronome), cursor and `pm-playing` highlight driven from the audio clock without a re-engrave, page follows the cursor, mute and solo per staff (Advanced mode), and `previewNote` bound to note entry. Catalog gains the B-flat clarinet and the double bass. `npm run size` budgets the playback chunk and the samples. See `docs/playback.md` and `docs/playback.fr.md`.
- Command palette, focus mode and cheat sheet (#11): `Ctrl+K` / `Cmd+K` opens a modal palette (ARIA 1.2 combobox and listbox) listing every command of the shortcut registry by group with its key badges, with accent-insensitive search over the French and English labels whatever the interface language, recently used commands first, commands unavailable in the current context shown disabled, focus restored on close; `Alt+F` focus mode (only the score and an "Esc to exit" pill, not persisted); `?` (QWERTY and AZERTY) opens a printable cheat sheet generated from the registry. The registry gains `group`, `paletteLabelKey`, `palette`, `sheet`, `enabled`, `run(id)`, a `Question` symbol key and ignores the keyboard while a modal dialog is open. The dialogs are one lazy chunk (about 3 KB gzip). See `docs/editor.md` and `docs/editor.fr.md`.
- Note entry with keyboard and mouse (#6): MuseScore default shortcuts (`N`, `3`–`7`, `.`, `0`, `A`–`G`, `Shift+A`–`G`, `+ - =`, arrows, `T`, `S`, `Ctrl+3`, `Del`, undo/redo) registered once in the shortcut registry, an input palette with key tooltips, an editor state store (score through `History`, selection, mode, duration, cursor), nearest-octave and key-signature aware pitch entry, automatic measure append and tied notes across barlines, click to select or to enter a note at the clicked pitch, `Shift` range selection, internal copy/paste, semitone/octave transposition, polite live-region announcements (English and French), an `onNoteEntered` hook for #10. `HitResult` gains an additive `tick`. - Engraving in `web/src/engraving/` (#4): the score model is rendered to SVG with VexFlow 5.11.0 (MIT, pinned, lazy-loaded so it stays out of the initial bundle). Our own layout engine (measure widths from content, proportional spacing, system breaking and justification, clef/key/time at system starts, courtesy changes, braces and brackets, part names, final barline, pickup measures), accidentals following key and measure, chords, dots, ties, slurs, triplets, beaming by beat, clef changes, `treble-8vb`, tab staves. Hit testing (`{partId, staffId, measureIndex, eventId, pitch}`) and event bounding boxes, theming from the design tokens with class-toggle selection and playback highlighting, incremental re-render (only the edited system is engraved again), `ScoreView` React component mounted in the editor paper area, accessible summary and live region hook. Unit tests, browser performance budgets and Linux visual baselines (`npm run test:visual:update`). Documented in `docs/engraving.md` and `docs/engraving.fr.md`.
- Editor shell (`#/editor`): top bar (editable title, save status, Share/Export placeholders, theme and language), collapsible instruments panel (`Ctrl+B`) and inspector (`Ctrl+I`, Advanced only), "paper" score area, status bar, shortcut reminder strip, persisted Simple/Advanced mode (`Alt+A`), overlay panels at 768 px, and a shared keyboard shortcut registry (`web/src/shortcuts/`) with macOS mapping. - Production container and release pipeline: multi-stage `Dockerfile` (chiseled, non-root .NET 10 runtime, digest-pinned bases), `docker-compose.yml` (app, one-shot `migrate` service, PostgreSQL 17, health checks, hardened container), `--migrate` and `--healthcheck` command-line switches, a `docker` CI job (build, compose smoke test, Trivy scan), a tag-triggered `release.yml` (multi-arch image on `ghcr.io/sputier/polymnia`, SBOM, provenance attestation, GitHub Release from this changelog), and the self-hosting and releasing guides (English and French).

### Changed
- Keystrokes stay under 16 ms when an edit moves line breaks (#38): after a re-flow the engraver engraves synchronously only the visible systems it can afford in a 6 ms budget (the one holding the selection first), the other visible ones on the next tasks and the rest in idle time; layout, hit testing and selection stay complete at once. The full-score highlight pass on every render is gone (about 4 ms on 100 measures). On 100 measures the p95 of a keystroke with a re-flow goes from 16.2 to 11.2 ms and the worst case of filling an empty score from 24.5 to 11.3 ms. The note-entry performance test now covers a filled score, a re-flow at the top and the filling of an empty score, and asserts p95 < 16 ms; `PLAYWRIGHT_PORT` selects the preview port. The engraver public API is unchanged. See `docs/engraving.md` and `docs/engraving.fr.md`.
- Faster editor start (#33): VexFlow is loaded from its `core` entry without embedded fonts; Bravura is a separate hashed `woff2` (same origin, immutable cache, preloaded when the editor mounts) and the Academico text font is dropped in favour of the UI font. The editor chunk goes from 468 KB to 180 KB gzip. The score is engraved progressively: the systems on screen first (first system in about 45 ms instead of 230 ms), the rest in idle time, with layout, hit testing and incremental edits unchanged. `npm run size` now also checks the editor chunk (200 KB gzip), the Bravura file (250 KB) and that no font is embedded in JavaScript. Added `THIRD_PARTY_NOTICES.md` (VexFlow MIT, Bravura/Inter/IBM Plex Mono SIL OFL 1.1). See `docs/engraving.md` and `docs/engraving.fr.md`.
