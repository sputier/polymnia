# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Security
- Authentication hardening (#7): Data Protection keys encrypted at rest with a certificate, mandatory outside Development (`DataProtection:CertificatePath`; compose mounts it as a secret, see `docs/authentication.md`); startup refuses `AllowedHosts` empty or `*` outside Development; per-IP rate limit with `429` and `Retry-After` on `/api/auth/*`; sign-in cookies expire after 10 minutes; structured audit events for sign-in, sign-out, failed sign-in and rate limiting (user id only); one database query per authenticated request for session and user.

### Changed
- The Content Security Policy now allows images from `https://*.googleusercontent.com` (Google avatars). An unsafe method on any `/api` route without a valid antiforgery token now answers `400`, before routing.

### Added
- Note entry with keyboard and mouse (#6): MuseScore default shortcuts (`N`, `3`–`7`, `.`, `0`, `A`–`G`, `Shift+A`–`G`, `+ - =`, arrows, `T`, `S`, `Ctrl+3`, `Del`, undo/redo) registered once in the shortcut registry, an input palette with key tooltips, an editor state store (score through `History`, selection, mode, duration, cursor), nearest-octave and key-signature aware pitch entry, automatic measure append and tied notes across barlines, click to select or to enter a note at the clicked pitch, `Shift` range selection, internal copy/paste, semitone/octave transposition, polite live-region announcements (English and French), an `onNoteEntered` hook for #10. `HitResult` gains an additive `tick`. See `docs/editor.md` and `docs/editor.fr.md`.
- Engraving in `web/src/engraving/` (#4): the score model is rendered to SVG with VexFlow 5.11.0 (MIT, pinned, lazy-loaded so it stays out of the initial bundle). Our own layout engine (measure widths from content, proportional spacing, system breaking and justification, clef/key/time at system starts, courtesy changes, braces and brackets, part names, final barline, pickup measures), accidentals following key and measure, chords, dots, ties, slurs, triplets, beaming by beat, clef changes, `treble-8vb`, tab staves. Hit testing (`{partId, staffId, measureIndex, eventId, pitch}`) and event bounding boxes, theming from the design tokens with class-toggle selection and playback highlighting, incremental re-render (only the edited system is engraved again), `ScoreView` React component mounted in the editor paper area, accessible summary and live region hook. Unit tests, browser performance budgets and Linux visual baselines (`npm run test:visual:update`). Documented in `docs/engraving.md` and `docs/engraving.fr.md`.
- Editor shell (`#/editor`): top bar (editable title, save status, Share/Export placeholders, theme and language), collapsible instruments panel (`Ctrl+B`) and inspector (`Ctrl+I`, Advanced only), "paper" score area, status bar, shortcut reminder strip, persisted Simple/Advanced mode (`Alt+A`), overlay panels at 768 px, and a shared keyboard shortcut registry (`web/src/shortcuts/`) with macOS mapping. Documented in `docs/editor.md` and `docs/editor.fr.md`.
- Production container and release pipeline: multi-stage `Dockerfile` (chiseled, non-root .NET 10 runtime, digest-pinned bases), `docker-compose.yml` (app, one-shot `migrate` service, PostgreSQL 17, health checks, hardened container), `--migrate` and `--healthcheck` command-line switches, a `docker` CI job (build, compose smoke test, Trivy scan), a tag-triggered `release.yml` (multi-arch image on `ghcr.io/sputier/polymnia`, SBOM, provenance attestation, GitHub Release from this changelog), and the self-hosting and releasing guides (English and French).
- Google sign-in with a server-side (BFF) session (#7): OpenID Connect authorization code flow with PKCE, `nonce` and `state`; session in a `__Host-` cookie (`HttpOnly`, `Secure`, `SameSite=Lax`) backed by a PostgreSQL session table (logout and user deletion end a session at once; sliding 7-day idle limit, 30-day absolute limit); Data Protection keys persisted in PostgreSQL; `users` table (no e-mail stored); `GET /api/me`, `GET /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/antiforgery`; antiforgery (cookie + `X-XSRF-TOKEN` header) on every unsafe request under `/api`; redirect URI built from `Auth:PublicBaseUrl`, local-only return URL; Production fails fast without Google settings. Front end: API client, sign-in screen (English and French), session state and sign-out. Documentation in `docs/authentication.md` and `docs/authentication.fr.md`.
- Continuous integration: `ci.yml` (jobs `web` and `api`: lint, type check, tests, build, bundle budget, Playwright, dependency audits), CodeQL analysis (JavaScript/TypeScript and C#), Dependabot (npm, NuGet, GitHub Actions, Docker), README badges and a "Continuous integration" section in the development and contributing guides (English and French).
- Score model in `web/src/score/` (pure TypeScript): integer ticks (960 per quarter), spelled pitches stored as written pitch with a per-part transposition, stable ids, sparse measure attributes with pickup measures, chords, ties, slurs, tuplets, clef changes, tab staves with fretting, and an instrument catalog (piano, voice, flute, violin, cello, classical and steel guitar, ukuleles) with tuning, capo and range helpers. Immutable with structural sharing; every edit is a command with apply, invert, unlimited undo and redo; semantic validation; versioned JSON serialization with a migration hook; JSON Schema draft 2020-12 in `schema/score.v1.schema.json` with size limits; fixtures; `npm run bench`. Format described in `docs/score-format.md` and `docs/score-format.fr.md`.
- Front-end skeleton in `web/`: Vite, React, TypeScript (strict), ESLint, Prettier, Vitest, Playwright, light and dark design tokens, self-hosted fonts, French and English i18n, and a bundle size budget check (initial JS at most 150 KB gzip). Development guide in `docs/development.md` and `docs/development.fr.md`.
- Project governance: README (English and French), MIT license, contributing guide, code of conduct, security policy, issue and pull request templates.
- Back-end skeleton (`api/`): ASP.NET Core on .NET 10, EF Core with PostgreSQL, `GET /api/health` and `/api/health/ready`, front-end hosting with SPA fallback and cache headers, Brotli/gzip compression, security baseline (HTTPS redirection, HSTS, CSP and other security headers, ProblemDetails without stack traces), optional forwarded headers, `docker-compose.dev.yml`, tests including Testcontainers PostgreSQL integration tests.

### Changed
- Faster editor start (#33): VexFlow is loaded from its `core` entry without embedded fonts; Bravura is a separate hashed `woff2` (same origin, immutable cache, preloaded when the editor mounts) and the Academico text font is dropped in favour of the UI font. The editor chunk goes from 468 KB to 180 KB gzip. The score is engraved progressively: the systems on screen first (first system in about 45 ms instead of 230 ms), the rest in idle time, with layout, hit testing and incremental edits unchanged. `npm run size` now also checks the editor chunk (200 KB gzip), the Bravura file (250 KB) and that no font is embedded in JavaScript. Added `THIRD_PARTY_NOTICES.md` (VexFlow MIT, Bravura/Inter/IBM Plex Mono SIL OFL 1.1). See `docs/engraving.md` and `docs/engraving.fr.md`.
