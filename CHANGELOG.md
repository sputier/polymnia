# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Security

- Authentication hardening (#7): Data Protection keys encrypted at rest with a certificate, mandatory outside Development (`DataProtection:CertificatePath`; compose mounts the `.pfx` and its password file, `DataProtection:CertificatePasswordFile`, as Docker secrets with mode 0400, see `docs/authentication.md`); startup refuses `AllowedHosts` empty or `*` outside Development; per-IP rate limit with `429` and `Retry-After` on `/api/auth/*`; sign-in cookies expire after 10 minutes; structured audit events for sign-in, sign-out, failed sign-in and rate limiting (user id only); one database query per authenticated request for session and user.

### Changed

- Engraving density (#46): tighter, engraving-like spacing in the editor and in the exports. Logarithmic duration spacing (`1 + 8 x log2(gap / 120 + 1)`, a quarter 26 px instead of 43), real glyph widths for noteheads, dots and accidentals, shorter clef, time and padding values (VexFlow's own room is the floor), smaller vertical gaps, a last system under 60 % full is no longer stretched, and abbreviated part names (`Pno.`, `Vln.`...: catalog short names in English and French) after the first system. Print size is a 1.75 mm staff space (`staffSpaceMm`, was 2.1 mm) and pages spread their leftover height between systems. A 4/4 piano score of quarter and half notes now has 4 to 5 measures per system and 100 measures take 3 A4 pages instead of 7. Visual baselines regenerated. See `docs/engraving.md`, `docs/export.md` and their French versions.
- The Content Security Policy now allows images from `https://*.googleusercontent.com` (Google avatars). An unsafe method on any `/api` route without a valid antiforgery token now answers `400`, before routing.

### Fixed

- On-screen piano lights the sounding pitch (#61): on transposing parts (guitar written an octave above the sound, B flat clarinet...) lit keys show the sounding pitch, and clicking a key or playing a MIDI note enters the written pitch that sounds as that key. Non-transposing parts are unchanged. See `docs/editor.md` and `docs/editor.fr.md`.

### Added

- Initial bundle back under 100 KB (#50): the initial JavaScript went from 147 KB to 75 KB gzip and its budget from 150 KB to 110 KB. One lazy chunk per screen (library, stored score, scratch editor, shared viewer, privacy), so the sign-in screen and the library no longer load editor code and the editor no longer loads library code; the new score and share dialogs and the command palette are chunks of their own, fetched in idle time; one lazy catalog per language (only the active one is loaded, the other on switch); `route-preload.js` (a build plugin) preloads the chunks of the screen in the address bar in parallel with `index.js`; the library prefetches the editor and the engraver when idle so opening a score is instant; `preloadable()` renders preloaded chunks without React's 300 ms Suspense fallback. `npm run build:report` and `npm run size:report` list the biggest modules of the initial chunks (bundle visualizer as a dev dependency); `npm run size` prints the JavaScript of each screen. Tests: the library requests no editor chunk, the editor requests no library chunk, switching language loads the other catalog, and cold-load times of the library and the editor on a throttled device (`@perf`). See `docs/development.md` and `docs/development.fr.md`.

- PDF export: Unicode text (#47). Titles, composer, part names, page numbers and any other text item beyond WinAnsi (Latin Extended, Greek, Cyrillic) are drawn as vector outlines of Inter (SIL OFL 1.1) instead of printing `?`, with an invisible text layer (render mode 3, Type0 font with a `ToUnicode` CMap) so the PDF stays searchable and pdf.js extracts the exact text. The outline tables (`web/src/export/inter/`, built by `scripts/export/build-text-outlines.mjs`) are four lazy chunks fetched only when a document has such text (a Cyrillic title loads about 35 KB gzip, a Latin-1 one nothing; the export chunk is 51 KB and each table has a 40 KB budget in `npm run size`); titles are fitted with Inter widths. CJK has no outline: drawn as `?`, reported (`pdf-text-U+XXXX`), still searchable. The PNG already used the browser fonts. See `docs/export.md` and `docs/export.fr.md`.
- Incremental score saves (#35): `PATCH /api/scores/{id}/content` applies operations on whole units addressed by stable ids (`setMeta`, `setMeasureInfo`, `setStaffMeasure`, `insertMeasure`, `deleteMeasure`, `replacePart`, `insertPart`, `deletePart`, `setSlurs`) to the stored `jsonb` document without it leaving PostgreSQL: one cheap query reads the document shape (ids and counts), the operations become `jsonb_set` / `jsonb_insert` / `#-` edits on bound parameters (consecutive replacements inside one array share a single rewrite of the document), applied in one `UPDATE` conditioned on the `If-Match` version (`409` on a stale version, two writers cannot both win). Every fragment is validated by the same compiled schema as a full save, the planner checks ids and counts (a patch can never store what a full save refuses, nor leave a staff without one measure per measure), the body is strict (1 MiB, 64 operations, 64 edits, no duplicate property) and the patched document is bounded by the same 4 MiB as a full save (`413`), a patch costs 1 + edits / 8 write permits. Same antiforgery, owner-only `404` and per-user rate limits as the other writes. The editor keeps the score the server holds, diffs the editor's score against it by reference identity (structural sharing: the cost follows the changed measures) and sends only the changed measures; it sends the whole document (`PUT`, gzip) for the first save after a conflict, for too many or too big changes (32 operations, 128 KB), and when the server answers `400` or `413` to a patch. A 1-measure autosave of a 500-measure score is about 40 ms p95 server side locally and 72 ms on a CI Linux runner (full `PUT` about 110 and 118 ms; 3 measures in 3 staves about 75 and 135 ms). Tests: every operation, rejected patches, size and edit limits, access control, antiforgery, concurrency, seeded random edit sequences giving the same document by patches and by full saves, the diff against random command sequences, the save queue and Playwright. See `docs/api.md`, `docs/library.md` and their French versions.

### Changed

- Keystrokes stay under 16 ms when an edit moves line breaks (#38): after a re-flow the engraver engraves synchronously only the visible systems it can afford in a 6 ms budget (the one holding the selection first), the other visible ones on the next tasks and the rest in idle time; layout, hit testing and selection stay complete at once. The full-score highlight pass on every render is gone (about 4 ms on 100 measures). On 100 measures the p95 of a keystroke with a re-flow goes from 16.2 to 11.2 ms and the worst case of filling an empty score from 24.5 to 11.3 ms. The note-entry performance test now covers a filled score, a re-flow at the top and the filling of an empty score, and asserts p95 < 16 ms; `PLAYWRIGHT_PORT` selects the preview port. The engraver public API is unchanged. See `docs/engraving.md` and `docs/engraving.fr.md`.
- Faster editor start (#33): VexFlow is loaded from its `core` entry without embedded fonts; Bravura is a separate hashed `woff2` (same origin, immutable cache, preloaded when the editor mounts) and the Academico text font is dropped in favour of the UI font. The editor chunk goes from 468 KB to 180 KB gzip. The score is engraved progressively: the systems on screen first (first system in about 45 ms instead of 230 ms), the rest in idle time, with layout, hit testing and incremental edits unchanged. `npm run size` now also checks the editor chunk (200 KB gzip), the Bravura file (250 KB) and that no font is embedded in JavaScript. Added `THIRD_PARTY_NOTICES.md` (VexFlow MIT, Bravura/Inter/IBM Plex Mono SIL OFL 1.1). See `docs/engraving.md` and `docs/engraving.fr.md`.
