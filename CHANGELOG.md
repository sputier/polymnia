# Changelog

All notable changes to this project are documented in this file.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Security
- Authentication hardening (#7): Data Protection keys encrypted at rest with a certificate, mandatory outside Development (`DataProtection:CertificatePath`; compose mounts the `.pfx` and its password file, `DataProtection:CertificatePasswordFile`, as Docker secrets with mode 0400, see `docs/authentication.md`); startup refuses `AllowedHosts` empty or `*` outside Development; per-IP rate limit with `429` and `Retry-After` on `/api/auth/*`; sign-in cookies expire after 10 minutes; structured audit events for sign-in, sign-out, failed sign-in and rate limiting (user id only); one database query per authenticated request for session and user.

### Changed
- Engraving density (#46): tighter, engraving-like spacing in the editor and in the exports. Logarithmic duration spacing (`1 + 8 x log2(gap / 120 + 1)`, a quarter 26 px instead of 43), real glyph widths for noteheads, dots and accidentals, shorter clef, time and padding values (VexFlow's own room is the floor), smaller vertical gaps, a last system under 60 % full is no longer stretched, and abbreviated part names (`Pno.`, `Vln.`...: catalog short names in English and French) after the first system. Print size is a 1.75 mm staff space (`staffSpaceMm`, was 2.1 mm) and pages spread their leftover height between systems. A 4/4 piano score of quarter and half notes now has 4 to 5 measures per system and 100 measures take 3 A4 pages instead of 7. Visual baselines regenerated. See `docs/engraving.md`, `docs/export.md` and their French versions.
- The Content Security Policy now allows images from `https://*.googleusercontent.com` (Google avatars). An unsafe method on any `/api` route without a valid antiforgery token now answers `400`, before routing.

### Added
- On-screen piano and MIDI keyboard input (#16) in `web/src/editor/piano/` (lazy chunk, fetched when the piano first opens): `P` shows a collapsible 88-key piano under the score, opened around the clef of the current staff; clicking a key enters the note at the current duration (`Shift` adds it to the chord) or, in select mode, changes the selected notes; keys are labelled buttons (French and English names), light up for the selected notes and during playback by class toggles outside React (no re-render per frame). Web MIDI is requested only from the "Connect MIDI keyboard" button: note-on enters notes, notes within 50 ms form a chord, several devices get a picker, hot-plug is handled, and unavailable (Safari, Firefox without its add-on) or denied access shows an explanation. Black keys are spelled from the key signature; sustain pedal and velocity are ignored in V1. Store method `enterMidi`. See `docs/editor.md` and `docs/editor.fr.md`.
- Read-only share links (#12): the owner shares a score from the top bar, the library card menu or the command palette (`Ctrl/Cmd+Shift+L`) with a dialog to create, copy, regenerate and revoke the link and to download a copy (the Export actions). The link is `/#/s/<token>`: a 256-bit random token in the URL fragment (never sent to a server, so out of access logs and `Referer`), stored as a SHA-256 hash only and shown once; one active link per score (enforced by a partial unique index); `GET /api/shared/{token}` is public, read-only by construction, answers a single identical `404` for unknown, revoked and malformed tokens, sends `Cache-Control: no-store`, `X-Robots-Tag: noindex` and `Referrer-Policy: no-referrer`, and is rate limited per client address (IPv4 or IPv6 `/64`, `RateLimiting:Shared:*`). Owner endpoints `GET`/`POST`/`DELETE /api/scores/{id}/share` (session, antiforgery, per-owner `404`); the creation answer carries the token and is never compressed. Links are deleted with the score or the user (`share_links`, migration `AddShareLinks`). The public viewer works signed out (score and playback bar, no editing interface, `noindex`), with the engraving and audio engine lazy-loaded. See `docs/sharing.md` and `docs/sharing.fr.md`.
- MIDI, PDF and PNG export (#14) in `web/src/export/` (lazy-loaded, 49 KB gzip, initial bundle unchanged): Standard MIDI File type 1 at 960 ticks per quarter (conductor track with tempo map, time and key signatures; one track per staff with its General MIDI program, channel 10 never used; timing reused from the playback timeline so ties, triplets and transposition match what you hear), PDF on A4 or Letter (chosen from the browser language, with a toggle in the menu) with title and composer, page numbers, vector output and always black ink on a white page whatever the theme, and PNG at 2x (one image, or a ZIP of pages). The PDF writer is our own (about 6 KB; jsPDF cannot embed the woff2/CFF Bravura): the engraver SVG is cut into pages and the music glyphs are drawn as vector outlines extracted from Bravura (`node scripts/export/build-glyphs.mjs`, dev dependency opentype.js, MIT). Export menu items, palette commands (`Ctrl/Cmd+Shift+U`, `F`, `G`), a progress panel, the export report dialog reused for anything dropped, an export chunk budget in `npm run size`. 100 measures: MIDI 1 ms, PDF 0.3 s, PNG 0.4 s. See `docs/export.md` and `docs/export.fr.md`.
- Score library and autosave (#9): the library is the signed-in home (`#/`) with a card list (instruments, measure count, last change, paged and infinite scroll), server-side title search (`/`), keyboard navigation between cards, new score dialog (title, instruments, key, time signature, tempo), rename, duplicate, share placeholder and delete with an 8-second undo (the request is deferred, so undo never touches the server); `#/scores/<id>` opens a stored score. Autosave with a serialized save queue (1 s debounce, 10 s maximum wait, one request at a time, gzip body, `If-Match` versions), save status in the top bar and status bar, retry with backoff when offline or on `5xx`, `Retry-After` on `429`, a clear message on `413`, a conflict dialog on `409` (load the server version or keep mine), a sign-in dialog on `401` that keeps the edits, `Ctrl+S`, a `beforeunload` warning, and saves that finish after leaving the editor. `GET /api/scores` items gain `measureCount` and `instruments`. ### Changed
- Keystrokes stay under 16 ms when an edit moves line breaks (#38): after a re-flow the engraver engraves synchronously only the visible systems it can afford in a 6 ms budget (the one holding the selection first), the other visible ones on the next tasks and the rest in idle time; layout, hit testing and selection stay complete at once. The full-score highlight pass on every render is gone (about 4 ms on 100 measures). On 100 measures the p95 of a keystroke with a re-flow goes from 16.2 to 11.2 ms and the worst case of filling an empty score from 24.5 to 11.3 ms. The note-entry performance test now covers a filled score, a re-flow at the top and the filling of an empty score, and asserts p95 < 16 ms; `PLAYWRIGHT_PORT` selects the preview port. The engraver public API is unchanged. See `docs/engraving.md` and `docs/engraving.fr.md`.
- Faster editor start (#33): VexFlow is loaded from its `core` entry without embedded fonts; Bravura is a separate hashed `woff2` (same origin, immutable cache, preloaded when the editor mounts) and the Academico text font is dropped in favour of the UI font. The editor chunk goes from 468 KB to 180 KB gzip. The score is engraved progressively: the systems on screen first (first system in about 45 ms instead of 230 ms), the rest in idle time, with layout, hit testing and incremental edits unchanged. `npm run size` now also checks the editor chunk (200 KB gzip), the Bravura file (250 KB) and that no font is embedded in JavaScript. Added `THIRD_PARTY_NOTICES.md` (VexFlow MIT, Bravura/Inter/IBM Plex Mono SIL OFL 1.1). See `docs/engraving.md` and `docs/engraving.fr.md`.
